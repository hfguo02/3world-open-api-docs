# Webhook 事件

3World 向白标商户配置的 Webhook URL 推送申请、卡片、交易和授信事件。

## 请求头

| Header | 说明 |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-Webhook-Id` | 事件 ID，与 Payload 的 `eventId` 相同 |
| `X-Webhook-Timestamp` | 本次投递的 Unix 时间戳，毫秒 |
| `X-Partner-Id` | 白标商户 ID |

Webhook 请求不包含签名 Header。商户应使用 `eventId` 做幂等处理，并通过 HTTPS、来源 IP 控制和事件数据校验保护接收端点。

## 请求体（Payload）

```json
{
  "eventId": "019be5c92817775c9efc4967016ac4ea",
  "eventCategory": "CARD",
  "eventType": "card.issued",
  "eventTime": "2026-01-24T13:00:00.000Z",
  "data": {}
}
```

请求体采用统一事件结构，`data` 的字段由 `eventType` 决定，详见各事件页面。

## 重试

- 连接和读取超时均为 2 秒。
- 任意 HTTP `2xx` 响应视为成功。
- 失败后最多重试 6 次，间隔为 1 分钟、5 分钟、30 分钟、2 小时、6 小时、24 小时。
- 重试沿用相同的 `eventId` 和请求体，每次发送会更新 `X-Webhook-Timestamp`。

商户端点应尽快返回 `2xx`，并异步处理耗时业务。
